# 本地知识库操作规范

## 1. 概述

| 项 | 说明 |
| --- | --- |
| 定位 | 本机知识库 = **资料库**（文档，支持 txt/md/pdf/docx）+ **项目记忆**（长期上下文），即用户**以硬盘为载体的超长上下文**：对话产生的知识沉淀于此，后续任意会话按需检索取用，不依赖模型上下文窗口 |
| 数据存储 | 仅保存在本机，不经云端（备份方式：复制数据目录，见 `kb_status`） |
| 访问通道 | `kb_` 前缀的 MCP 工具（本规范）；同一数据亦可经 `api/ai` HTTP 接口访问 |
| 管理界面 | 桌面客户端 LocalKnowledgeBase.Desktop（编辑、删除、批量导入） |
| 模型要求 | **无**。本知识库只提供检索与存储，与所使用的模型（云端 API 或本地部署）无关 |

## 2. 工具清单

| 工具 | 作用 | 使用时机 |
| --- | --- | --- |
| `kb_status` | 服务状态、数据目录 | 排查连接问题的第一步 |
| `kb_get_context` | 检索并打包成带 [n] 编号引用的提示词上下文，支持 `max_chars` 总预算 | 回答知识库相关问题前，**优先使用**；预算用于控制 token 消耗 |
| `kb_search_documents` | 全文检索文档（返回摘要与编号） | 需要浏览多条结果时 |
| `kb_get_document` | 读取指定文档全文 | 上下文摘要不够、需要引用原文时 |
| `kb_add_document` | 将文本内容保存为新文档 | 用户要求沉淀结论、笔记进知识库 |
| `kb_search_memory` | 按关键词检索项目记忆 | 查找偏好、决策、约定 |
| `kb_list_memory` | 列出全部记忆条目 | 用户要求浏览记忆 |
| `kb_get_memory` | 读取指定记忆全文 | 需要某条记忆的完整内容 |
| `kb_save_memory` | 新建或更新记忆条目 | 见第 3.2 节 |

## 3. 操作规范

### 3.1 检索与回答

1. **必须**：回答依赖知识库内容的问题前，先执行检索（优先 `kb_get_context`）。
2. **必须**：回答中引用来源时使用 `[1]`、`[2]` 编号并附文档标题；编号与来源工具返回一致。
3. **必须**：检索无命中时如实说明"知识库中没有相关资料"，**禁止编造资料内容**。
4. **应当**：摘要不足以回答时，用 `kb_get_document` 取全文后再回答。

### 3.2 保存记忆

**触发条件**：用户明确要求"记住…"时必须保存；对话中出现以下内容时应当主动提议保存——
用户的长期偏好（语言、代码风格、工具链）、重要决策及其理由、项目约定、可复用的结论。

**操作规则**：

1. **必须**：保存前先用 `kb_search_memory` 查重；已存在同类条目时把其编号填入 `id`
   进行更新，禁止创建重复条目。
2. **必须**：`title` 为一句话概括（如"用户代码偏好"）；`content` 使用要点式简洁表述；
   `tags` 使用逗号分隔的主题词（如"偏好,工作流"）。
3. **必须**：保存成功后向用户报告条目编号与标题（例："已存入记忆 d52b84a4 用户偏好与项目约定"）。
4. **禁止**：删除记忆。工具不提供删除能力；用户要求删除时，引导其在桌面客户端
   "项目记忆"页操作。

### 3.3 沉淀文档

1. **触发条件**：用户要求"存进知识库/整理成文档"，或讨论产生值得留存的结论。
2. **必须**：`title` 一句话概括；`fileName` 以 `.md` 或 `.txt` 结尾（不得使用 .pdf/.docx，
   那两类仅用于桌面客户端导入真实文件）。
3. **必须**：保存成功后报告文档编号与标题。
4. **禁止**：删除文档。用户要求删除时，引导其在桌面客户端"资料库"页操作。

### 3.4 故障处理

1. 工具返回"无法连接本地 API"时，**应当**主动执行：
   `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-api.ps1`
   等待约 10 秒后重试一次；仍失败则向用户报告，并建议检查
   `http://localhost:5062/api/knowledge-base/status`。
2. 需要确认服务与数据目录时调用 `kb_status`。

### 3.5 会话存本（对话知识沉淀）

用户的核心工作流：**每次对话产生的知识都以“存本”形式进入知识库，作为后续会话的长期上下文**。

**触发条件**：

1. 用户说“存本 / 收尾 / 把这次对话存下来 / 结束前保存”时**必须**执行；
2. 对话中产生了明确的知识增量（完成的配置、排查结论、新决策、重要事实）且尚未入库时，
   **应当主动提议**（一次会话提议不超过一次，避免打扰）。

**操作流程**：

1. 回顾本次对话，提炼知识增量：结论、决策及理由、关键配置/命令、排查过程与结果、
   用户偏好变化。与本次对话任务本身无关的过程性内容不收录。
2. `kb_search_memory` 查重：已有同类条目则更新（填 `id`），避免碎片化重复。
3. `kb_save_memory` 保存，格式约定：
   - `title`：`会话存本：<本次对话主题>`（如“会话存本：知识库语义检索接入”）；
   - `content`：要点式，按“结论 / 决策 / 配置与命令 / 待办”分小节，命令必须带完整路径与参数；
   - `tags`：`会话存本` + 1~3 个主题词（如“会话存本,检索,embedding”）。
4. **必须**：保存后向用户报告编号、标题与收录要点数。

**后续会话使用**：用户引用历史（“上次/之前/我们之前决定…”）或任务与已存主题相关时，
先 `kb_search_memory`（可按 tags `会话存本` + 主题词）检索，再基于检索结果回答；
`kb_get_context` 同样覆盖会话存本条目。

### 3.6 Token 消耗控制

知识库可能很大，检索结果必须节制：

1. **必须**：回答前取上下文用 `kb_get_context`，并按任务规模设置 `max_chars` 预算
   （默认 4000 字符；简单问题 1000~2000，综合任务 4000~8000）——超预算的低相关条目
   会被自动舍弃，返回体中“因预算舍弃”为 true 时说明还有未装入内容。
2. **必须**：只有当上下文摘要不足以回答时才 `kb_get_document` 取全文，且仅在需要
   精确引用原文时取。
3. **禁止**：为“保险起见”把大量文档全文塞进对话；先摘要后全文是默认顺序。
4. **应当**：命中条数多时先向用户复述检索范围（命中数/已装入/舍弃），由用户决定是否扩大。
5. **必须**：同一会话内同一主题只检索一次——再次被问及时直接引用已有结果与编号，
   重复检索会让结果反复驻留上下文、成倍放大 token 消耗。

## 4. 数据与安全边界

1. 全部数据保存在本机；`kb_*` 工具不提供任何删除能力，防止 AI 误删。
2. 知识库内容可能包含未公开信息：检索结果仅用于当前对话，不得主动发送至其他服务。
3. 用户要求批量导入、编辑、删除时，引导其使用桌面客户端（支持拖拽与多选导入）。
